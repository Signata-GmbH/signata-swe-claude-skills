# Common workflow discipline (both flavors)

> Loaded by all three module skills regardless of `project.type`. This is the
> shared backbone — harmonized up from the stronger patterns across the AUTOSAR and
> non-AUTOSAR prompts. Flavor packs (`autosar/`, `generic/`) layer the
> project-type-specific mechanics on top; they never restate this file.

## 0. Standalone & idempotent — NO pipeline assumption

- **Any skill may be the first to run for a module.** Never assume Code Dev (or
  any other skill) ran first, or that a module was generated by a skill at all.
- On every run, ensure `20_AI/ai_project.yaml` and `20_AI/manifests/<MODULE>.yaml`
  exist. The **manifest** is per-module — scaffold + confirm it here (§3). The
  **project config** is per-repo and belongs on the base branch: it is owned by
  the `project-init` skill, so a missing one goes through
  [project-config.md](project-config.md) §7 (stop if it already exists on the base
  branch or is in flight elsewhere; otherwise `/project-init`, or bootstrap inline
  when already on the base branch) — never scaffold a competing copy on a feature
  branch.
- **Populate only your own workflow section.** The three sections
  (`code_dev` / `code_review` / `unit_test`) are independent; another's
  `last_run` may be `null` and that is valid.
- Review and test operate on **whatever code is actually present**. Absent
  Code-Gen artifacts (traceability comments in a given form, an
  Implementation_Review.md, …) are **findings, not blockers**.

## 1. Pre-flight & input acquisition (before any analysis) — FAIL-CLOSED

### 1.1 Required inputs per skill

| Document (config/manifest key) | unit-test | code-review | code-dev |
|---|:--:|:--:|:--:|
| SW Requirements workbook (`requirements.workbook`) | ✔ | ✔ | ✔ |
| Module source `<MODULE>.c/.h` / Agnosar stub + RTE interface | ✔ | ✔ | ✔ |
| SDD (`manifest docs.sdd`) | ✔ | ✔ | ✔ |
| Signals & Parameters (`docs.signals_params`) | ✔ | ✔ | ✔ |
| Architecture Design Document (`docs.architecture` — project or module) | ask | ask | ask |
| Coding guideline (`docs.coding_guideline`) | – | ✔ | non-AUTOSAR ✔ / AUTOSAR opt |
| Review checklist workbook (`docs.checklist`) | – | ✔ | – |

✔ = mandatory · **ask** = optional but must be **explicitly offered** at the gate ·
– = optional (recorded if present). Any document may be **`.pdf` or `.xlsx`**.

### 1.2 Fail-closed acquisition loop

**Never self-substitute or self-waive.** You must **not** set any document to
`N/A` on your own reasoning, and **never** treat one document as fulfilling
another's role (e.g. the SDD does **not** satisfy the Architecture input). Only an
**explicit engineer decision at this gate** resolves a missing input. A deliverable
authored on a silently-substituted input is invalid.

For each input in the skill's required set, in order:
1. Resolve its path from config/manifest to a **real, readable** file. A document
   may be **`.pdf` or `.xlsx`** — accept either.
2. If missing / unreadable / placeholder → **explicitly ask the engineer** to
   provide it (path or attach), then write the answer back: project-wide docs →
   `ai_project.yaml`; per-module docs → the manifest.
3. Resolve by tier:
   - **Mandatory** (✔) not provided → **hard STOP** — report which one and why.
   - **Ask** (optional-but-prompted, e.g. the Architecture Design Document) →
     **explicitly offer it and ask** whether to provide one; proceed without it
     **only if the engineer explicitly declines**, recorded as `N/A` + a one-line
     reason. Never skip the prompt and never infer the answer.
   - **Optional** (–) missing → note and proceed.
4. Also offer to attach any **extra** documents and free-text **run instructions**
   for this run (manifest `docs.extra` / `docs.run_instructions`).

Emit a pre-flight table: `input | required? | resolved path | present & readable? |
acquisition outcome`. **Never emit a deliverable while a mandatory input is
unresolved** — a "complete-looking" artifact produced without its rubric is worse
than an honest stop.

## 2. Revision pinning (the audit spine)

- Record `git rev-parse HEAD` and `git hash-object <file>` for every source file
  you read; check out the SHA in scope if one is given.
- **Every symbol, guard, and expected value is valid only at that revision.**
  Carry the SHA (and blob hashes) into the outputs and the ledger (§9). A branch
  can rename/retype globals between lineages — a wrong revision produces failures
  that look like defects but are not.

## 3. Manifest: scaffold → validate → confirm (HARD GATE)

> Per-**module** manifest only. The per-repo `ai_project.yaml` follows
> [project-config.md](project-config.md), not this section.

- Compute the derivable values from config: `module.upper`, `unit_test.env`, all
  layout paths, doc locations.
- **Read** the manifest. If **absent**, derive fields + discover the input docs
  (glob under `docs.root`), scaffold from `manifest-template.yaml`, and **present
  it for confirmation**. If **present**, validate required fields for this flavor;
  flag/repair anything malformed rather than proceeding on it.
- Collect inputs the friendly way: **`AskUserQuestion` popup** for categorical
  choices (scope = all/subset, requirement filter); **discovery → popup** when a
  glob finds several candidate docs (pick one); typed values only for the
  genuinely unknowable (module name as the command argument).
- **Requirements-count gate (mandatory).** After applying the requirement
  filter/scope, report the resulting count and **require the engineer to confirm
  or enter the expected count** before proceeding — persist it as
  `expected_row_count`. Never silently learn it; a mismatch on a later run halts
  (§9). This guarantees the requirement scope is aligned as intended.
- **STOP and wait for confirmation** before doing any work.

## 4. Grounding & no silent assumptions

- **Symbol grounding:** every identifier that is not a subprogram parameter is
  copied **verbatim** from the sources the flavor pack whitelists — never from
  test/analysis/generated/release artifacts or another branch. Self-check before
  emitting; list any symbol you cannot confirm and **stop** rather than guess.
- **Discover before define:** before hardcoding a constant/mask/mapper/threshold,
  grep the project for an existing macro or helper and reuse it.
- **No silent assumptions:** every ambiguity, mismatch, or gap becomes a numbered
  Phase-1 question **or** a Deferred Items row — never a silent guess.

## 5. Phase-1 questions → workbook (offline-answerable)

- Write the numbered questions to a **skill-namespaced** workbook
  `20_AI/<MODULE>_Phase1_Questions_<Skill>.xlsx` (`<Skill>` = `UnitTest` /
  `CodeReview` / `CodeDev`) so the three skills never clobber each other's
  questions. One row each: `QID | Requirement | Function | Question | AI Proposal |
  Answer(blank) | Status(open)`.
- If the workbook already exists, **read it back first**: rows with a non-empty
  `Answer` (or `Status` = `answered`/`deferred`) are resolved — carry them forward
  and re-emit only still-`open` rows under their existing `QID`s.
- **Every question cites `file:line` evidence** for the claim it rests on; never
  ask the engineer to arbitrate a discrepancy you have not shown with concrete
  citations.

## 6. Gate Table discipline (for every asserted effect / emitted action)

Produce one row per external call or global write you assert (test) or emit (dev):

`asserted/emitted effect | writing statement file:line | full guard condition | each conjunct → what controls it → value this case sets`

- **Quote every conjunct** — a 4-term `&&` guard needs four entries.
- **Set stub-controlled conjuncts explicitly** — never rely on the auto-stub
  default `0`; in these codebases `0` is a live enum value and a defaulted stub
  routes execution down a *real* branch.
- **Distinguish the selector global from the value-source global** — setting the
  branch selector but leaving the written value at its default asserts the wrong
  thing.
- If a conjunct **cannot hold** under the case's inputs, the effect is
  unreachable — change inputs or drop the assertion.
- A conjunct controlled by a variable **never written outside its initialiser** →
  report as a **code finding**; do not fake a case that reaches it.

## 7. Fidelity rules (dev authors them; review checks them)

- **Preserve precondition gates** — reproduce every guard the requirement/design
  calls for, in the specified order, each with a `/* SW_Req(u)-NNN: rationale */`.
- **Failure-mode fidelity** — implement the literal failure behaviour ("hold last
  valid", "stop motor", "default to X"), not a generic fail-safe.
- **Signal-mapping fidelity** — source signal, scaling, and encoding come from the
  requirement / LDF / design, never inferred from a variable name.

## 8. Traceability

- Every non-trivial branch/assignment (dev), test case (test), and finding
  (review) carries its requirement ID **or** a structural / `COVERAGE-ONLY` label
  naming the exact decision it targets.
- **Cite a requirement ID only when the artifact asserts that requirement's
  Expected Result** — otherwise it is structural, not requirement-traced.

## 9. Ledger & run history (audit)

Two records with different jobs (see also the manifest template):

- **`last_run:` in the manifest — working state, overwritten each run.** Holds the
  latest snapshot the in-place diff needs: timestamp, `skill_version`,
  `source_sha` + blob hashes, requirements snapshot (`ID → {hash, cases/files}`),
  and the delta. This drives re-runs; it is **not** history.
- **`20_AI/manifests/history/<MODULE>.jsonl` — append-only audit trail.** After
  each run, **append** one immutable JSON record (never edit prior lines):
  `{ts, wf, skill_v, sha, reqs_sha, delta:{added,updated,removed}, notes}`. Render
  it to a Markdown table only when asked. Git is a second corroborating trail.

**In-place re-run** (the reason `last_run` exists): recompute each in-scope
requirement's hash and compare to `last_run.requirements`:
- **new** (ID absent) → author the artifact, append.
- **changed** (hash differs) → **update the mapped artifact in place** (keep its
  name/history stable), tag it revised.
- **removed** (was present, now absent) → **flag it; never silently delete** —
  surface the orphaned case/finding for the engineer to decide.
- **unchanged** → leave untouched.
Show the delta and **confirm before writing**.

## 10. No fabrication

See [no-fabrication.md](no-fabrication.md). No toolchain runs here — never claim a
build, static-analysis, or test result you did not produce.
